# Публикация сайта на GitHub Pages

Репозиторий уже создан: **`C:\Users\user\Desktop\svadba`** (в нём лежит сайт).
GitHub Desktop установлен. Осталось закоммитить файлы, отправить их на
GitHub и включить Pages.

Итог: постоянная ссылка вида

```
https://ваш-логин.github.io/svadba/
```

---

## Почему раньше в Pages не было папки / (root)

GitHub Desktop создал репозиторий по шаблону: в ветке `main` был только
служебный `README.md`, файлов сайта (`index.html` и других) там не было.
Список папок в **Settings → Pages** пустой, пока в ветке нет содержимого.
Сейчас файлы уже скопированы в `Desktop\svadba` — осталось их отправить.

---

## Шаг 1. Проверьте ветку в GitHub Desktop

Откройте GitHub Desktop и убедитесь, что сверху выбрано:

- **Current repository:** `svadba`
- **Current branch:** `main`

Если ветка называется `master` — меню **Branch → Rename…** → введите `main`
→ **Rename branch**.

## Шаг 2. Закоммитьте файлы

1. Слева появится список из ~12 файлов (index.html, styles.css, app.js,
   assets, README.md и другие). Это нормально, они новые.
2. Внизу слева в поле **Summary** напишите: `Свадебный сайт Аня и Никита`
3. Нажмите синюю кнопку **Commit to main**.

## Шаг 3. Отправьте на GitHub

1. Наверху нажмите **Publish repository** (если репозиторий ещё не на GitHub)
   или **Push origin** (если уже публиковали).
2. В окне публикации:
   - **Name:** `svadba`
   - снимите галочку **Keep this code private** — для бесплатного
     GitHub Pages репозиторий должен быть публичным;
   - нажмите **Publish repository**.

## Шаг 4. Включите Pages

1. Откройте https://github.com → репозиторий `svadba`.
2. Убедитесь, что на главной странице репозитория видно файл `index.html`
   (и папку `assets`). Если видно только `README.md` — вернитесь к шагу 2–3.
3. **Settings** → слева **Pages**.
4. **Build and deployment:**
   - **Source:** `Deploy from a branch`
   - **Branch:** `main`, папка `/ (root)`
5. Нажмите **Save**.

Теперь в выпадающем списке папка `/ (root)` есть — она означает «сам
`index.html` в корне репозитория».

## Шаг 5. Проверьте ссылку

Ссылка появится на странице Pages сверху:

```
https://ваш-логин.github.io/svadba/
```

Первый деплой занимает 1–3 минуты (иногда до 10). Если видите 404 —
подождите и обновите страницу.

---

## Как обновлять сайт

1. Меняете текст в `index.html` или добавляете фото в `assets`
   (в папке `C:\Users\user\Desktop\svadba`).
2. GitHub Desktop → **Summary** → **Commit to main** → **Push origin**.
3. Через 1–2 минуты правки появятся по той же ссылке.

## Если в Pages написано «Your site is having problems building»

Проверьте: файл называется именно `index.html` (не `Index.html`),
и он лежит в корне репозитория, а не внутри вложенной папки.

## Своя короткая ссылка (необязательно)

Длинный адрес можно сократить:

- купить домен вида `anya-nikita.ru` и подключить в
  **Settings → Pages → Custom domain**;
- или сделать короткую ссылку бесплатно (clck.ru, bit.ly) и разослать её.

## Важно про ответы гостей

Кнопки «Иду / Не иду» сейчас сохраняют ответ в браузере гостя и показывают
благодарность, но **вам ответ не приходит**. Чтобы ответы падали в Telegram,
впишите токен бота и `chat_id` в `app.js` — раздел «Чтобы ответы гостей
приходили вам» в `README.md`.
